# Автоматизированный тест Vanessa Automation

## Сценарий

Файл сценария: `features/ОбслуживаниеКлиентов.feature`

Тест проверяет полный цикл:
1. Планирование обслуживаний от имени Менеджера.
2. Закрытие обслуживаний от имени Специалиста.
3. Массовое создание актов от имени Бухгалтера.
4. Формирование отчёта «Анализ выставленных актов» и сравнение с эталоном.

---

## 1. Подготовка базы

### 1.1. Требования

- Платформа **1С:Предприятие 8.3.24 и выше** (или актуальная).
- Конфигурация с поддержкой **БСП** (Библиотека Стандартных Подсистем) версии **3.1 и выше**.
- **Vanessa Automation** версии **1.2.0 и выше** (установлена как внешняя обработка или встроена).

### 1.2. Создание тестовой базы

1. Создайте **пустую информационную базу**.
2. Загрузите в неё вашу конфигурацию (`.cf` или `.cfe`).
3. Обновите конфигурацию базы данных (F7).
4. **Не используйте** базу с реальными данными — тест изменяет данные.

### 1.3. Заполнение начальных данных

Перед запуском теста в базе должны быть:

**Справочники:**
- `Организации` — хотя бы одна организация.
- `Контрагенты` — «ОАО Абон».
- `ДоговорыКонтрагентов` — «АбонОбсл» с видом «Абонентское обслуживание», заполненными датами, суммой абонплаты, стоимостью часа.
- `Сотрудники` — «Менеджер», «Администратор», «Специалист» (или использовать существующих).
- `Номенклатура` — элементы «Абонентская плата», «Работа специалиста».
- `Пользователи` — «Менеджер», «Специалист», «Бухгалтер» с соответствующими профилями.

**Константы:**
- `НоменклатураАбонентскаяПлата` — «Абонентская плата».
- `НоменклатураРаботыСпециалиста` — «Работа специалиста».
- `ТокенУправленияТелеграмБотом` — тестовый токен (можно пустой).
- `ИдентификаторГруппыДляОповещения` — тестовый ID (можно пустой).

**Регистр сведений `УсловияОплатыСотрудников`:**
- Записи за месяц теста (например, июнь 2026):
  - «Менеджер»: оклад = 30 000, процент = 10.
  - «Администратор»: оклад = 40 000, процент = 0.
  - «Специалист»: оклад = 25 000, процент = 15.

### 1.4. Настройка прав доступа

В менеджере пользователей создайте пользователей:

| Имя | Пароль | Профиль |
|---|---|---|
| Менеджер | (пусто) | Менеджер |
| Специалист | (пусто) | Специалист |
| Бухгалтер | (пусто) | БухгалтерИТФирмы |

### 1.5. Очистка данных перед запуском

Перед каждым запуском теста рекомендуется **очищать**:

- Документы «Обслуживание клиента» за тестовый период.
- Документы «Реализация товаров и услуг» за тестовый период.
- Регистр `ВыполненныеКлиентуРаботы` за тестовый период.

Это можно сделать **вручную** или через **обработку**.

## 2. Настройка Vanessa Automation

### 2.1. Установка

1. Скачайте **Vanessa Automation** с [официального репозитория](https://github.com/vanessa-opensource/add).
2. Откройте обработку в 1С:Предприятие.
3. Укажите путь к папке с `features/` (в настройках Vanessa).

### 2.2. Настройки запуска

В форме Vanessa Automation (epf) выберите файлы тестирования

### 2.3. Настройки подключения

- **Имя пользователя**: `Администратор` (или пользователь с полными правами).
- **Пароль**: (пусто).

### 2.4. Запуск

1. Откройте Vanessa Automation в 1С:Предприятие.
2. Нажмите **«Загрузить фичи»**.
3. Выберите `ОбслуживаниеКлиентов.feature`.
4. Нажмите **«Выполнить сценарии»**.

---

## 3. Интерпретация результатов

После запуска Vanessa Automation:

- **Зелёные шаги** — успешно.
- **Красные шаги** — ошибка.
- В конце — отчёт **Allure** (если включён).

При ошибке:
1. Откройте скриншот (если формируется).
2. Проверьте журнал регистрации 1С:Предприятие.
3. Убедитесь, что тестовые данные заполнены.

---


## 5. Обновление эталона

Если бизнес-логика изменилась:

1. Откройте отчёт «Анализ выставленных актов» за тестовый период.
2. Сформируйте на эталонных данных.
3. Сохраните как `.mxl` в папку `features/Эталоны/`.
4. Закоммитьте в репозиторий.
