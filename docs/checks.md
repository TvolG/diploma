# Проверка на компьютере с 1С

Среда разработки не содержит платформу и EDT. Проверки ниже обязательны до приёмки и выпуска DT; они не отмечены как выполненные.

## Установка

1. Возьмите ветку `fix/screenshot-review-20261112`, сделайте резервную копию существующей базы. Откройте `fonecmid-diplom` в EDT с платформой 8.3.27, дождитесь валидации. Сохраните список ошибок EDT. Обновляйте тестовую копию, а не рабочую базу.
2. Выполните проверку конфигурации в Конфигураторе: синтаксис серверных, тонкого и веб-клиентских модулей; ссылки и логическая целостность. Исправления UUID должны распознаться как переименования, не как удаление накопленных данных.
3. Запустите Предприятие под администратором и завершите обновление БСП. Выполните начальную настройку из README. При обновлении старой базы отдельно проверьте договоры, документы начисления и записи условий: новые обязательные периоды не восстанавливаются из предположений.

## Проверки ошибок и расчётов

| Проверка | Ожидается |
|---|---|
| Открыть пустой/записанный график отпусков | Нет ошибок `УсловноеОформление` и `Очистить`; очистка выполняется у коллекции `Элементы` |
| Две строки одного сотрудника по 15 дней | Обе выделены (>28 суммарно); удалить строку — выделение снимается |
| Открыть анализ графика другого года, два интервала одного сотрудника | Правильный год, одна строка сотрудника, оба интервала; нет отсутствующих обработчиков |
| Открыть договор абонобслуживания; сменить вид | Поля сразу видны, порядок начало/окончание/плата/ставка; при другом виде скрыты |
| Подменить договор чужим клиентом программно/через форму | Запись/проведение отклонено сервером |
| Повторно заполнить реализацию | В услугах одна абонплата и одна агрегированная работа; количество строк не растёт |
| Массовое создание без предварительного заполнения | Список получается автоматически, запускается фон БСП |
| Два запуска создания за один месяц | Не появляются новые акты или повторные услуги; проверить также два сеанса одновременно |
| Работа 2 часа × 1000, условия 10% | Клиентский регистр 2000, сотруднику 200; 0% допустим; отсутствующая запись условий — ошибка |
| Изменить процент без перепроведения старой работы | Старое вознаграждение в регистре сохраняется |
| Календарь: 20 рабочих дней, оклад 30000, отпуск вытеснил 5 рабочих дней | Оклад 22500. Для базы отпуска 360000/240 и 7 календарных дней — отпускные 10500 |
| Отпуск, фиксированная премия и процент | Суммы входят в историю, база — предшествующие 12 полных месяцев; текущий месяц не входит |
| Повторно провести начисление, затем пересчитать после исправления истории | Движения не удваиваются; хронологический пересчёт обновляет зависимые начисления |
| Начислено 10000, НДФЛ 1300, выплачено 2000 | Остаток к выплате 6700. Будущие начисления не включены; повторное проведение выплаты не меняет остаток само по себе |
| Отчёт актов: несколько работ и актов клиента по разным договорам | Нет размножения строк/смешивания договоров; абонплата и другая услуга не входят в «Сумма акта» |
| Отключить пользовательский период / сформировать с настройками по умолчанию | Обязательные границы запроса остаются заданы |
| Открыть каждый документ и его движения | Доступны связанные регистры; запись/перепроведение не меняют посторонние движения |
| Печать акта через БСП | Все строки, сумма, пропись и подписи; изменение общего макета применяется |

Проверяйте серверный и клиентский контекст на реальной платформе. Статический разбор не проверяет существование методов API, названия полей виртуальных таблиц и сериализацию форм EDT.

## Права

Заново войдите под каждым профилем: менеджер, специалист, бухгалтер, кадровик-расчётчик. Используйте поставляемые профили БСП, а не одну роль вручную. Проверьте запуск тонкого клиента, видимость разделов, чтение зависимых справочников, запись разрешённых документов, отчёты, файлы/печать и отказ доступа к чужим операциям. Под администратором должны быть видны оба новых раздела.

## Демобаза и Vanessa

После успешной загрузки создайте данные 2026 года командой обработки настройки в отдельной копии. Проверьте фактические количества: минимум 5 элементов новых бизнес-справочников, документы с тремя строками, минимум 10 детальных строк каждого отчёта. Генератор подготовлен, но в этой среде не выполнялся. Обязательные поля справочников поставщика и API присоединения файлов требуют нативного прогона.

Сохраните чистую копию демобазы перед автотестом. Сценарий `tests/features/01_ОбслуживаниеКлиентов.feature` рассчитан на неё и изменяет данные. Для каждого повторного прогона восстановите копию; канонический DT экспортируйте до сценария либо из восстановленной копии.

В таблице клиентов тестирования Vanessa создайте подключения к одной тестовой базе:

| Имя клиента | Пользователь ИБ |
|---|---|
| Менеджер | ВКМ_Демо_Менеджер |
| Специалист | ВКМ_Демо_Специалист |
| Бухгалтер | ВКМ_Демо_Бухгалтер |

Запустите тонкие клиенты с разрешением тестирования; порты каждого подключения должны различаться. Пароли задайте локально. В параметрах Vanessa задайте переменную `КаталогПроекта` — абсолютный путь клона на машине клиента тестирования. Сценарий использует `tests/fixtures/time-sheet.png`. Проверьте, что версия Vanessa поддерживает шаг ожидания строк таблицы и подстановку переменных. Имена базовых шагов сверялись с исходниками Vanessa, commit `08e27ef`; реальный прогон здесь отсутствует.

Особенно проверьте записью шагов: открытие штатного диалога стандартного периода (`DateBegin`, `DateEnd`, `Select`) и переход в «Присоединенные файлы»/`ДобавитьИзФайлаНаДиске`. Они могут отличаться в конкретной версии платформы и настройках интерфейса. Это подготовленный сценарий, не готовый протокол успешного запуска. Старые `Manager.feature`, `Worker.feature`, `Accountnt.feature` в корне оставлены как исторические записи и не являются новым набором приёмки.

Независимый эталон: `tests/fixtures/act-report-reference.csv`. По каждому из первых трёх договоров: исходные 6000 + 3 новых часа × 1000 = 9000. По остальным двенадцати — 6000. Итого работы/акты по 99000. Месячная плата 10000 и дополнительная услуга 2500 исключены из сравниваемой суммы работ акта. Сценарий сравнивает 15 строк, затем повторяет создание и сравнение. Не создавайте эталон сохранением фактического отчёта: это скроет ошибку.

Сохраните логи Vanessa, снимки ошибок и четыре отчёта; передайте точный текст ошибки и объект при несовпадении. После успешной проверки можно выгрузить актуальный DT.

## Выгрузка

Закройте пользовательские/тестовые сеансы, восстановите проверенную каноническую демобазу. Используйте Конфигуратор → Администрирование → Выгрузить информационную базу либо `scripts/export-checked-demo.ps1`. Скрипт работает с уже обновлённой файловой базой, не конвертирует EDT и не подтверждает тесты автоматически. Передайте ему `-RuntimeChecksPassed` только после перечисленных проверок.

Пример PowerShell:

```powershell
./scripts/export-checked-demo.ps1 -OneCExe 'C:\Program Files\1cv8\8.3.27.XXXX\bin\1cv8.exe' -DatabasePath 'C:\1C\DiplomaDemoChecked' -OutputDt 'C:\1C\release\DIPLOMA.dt' -User 'Администратор' -RuntimeChecksPassed
```

Затем загрузите DT в новую пустую базу и ещё раз проверьте вход/отчёты. Приложите файл к новому GitHub release с указанием проверенного коммита, версии платформы и результатов. Существующий `dtbase` содержит старую выгрузку; автоматически он не изменялся.
